# 자기평가

## 완료한 것

- 오늘, 기록하기, 기록, 주간 리포트의 네 화면을 조작할 수 있습니다.
- 첫 GET은 `FutureBuilder<AppData>`로 waiting, error, empty, success를 처리합니다.
- 감정, 태그와 메모 선택 상태는 `setState()`로 갱신합니다.
- 새 기록은 이번 실행 중 오늘 요약과 기록 화면에 반영됩니다.
- 주간 리포트는 오늘 새로 남긴 기록을 별도 카드로 표시합니다.
- 오늘 화면에서 기록 화면으로 이동할 때 `Navigator.push`를 사용합니다.
- 기록 날짜의 상세 내용은 `showModalBottomSheet`로 표시합니다.
- 정상, 로딩, 빈, 오류 상태를 메뉴에서 확인할 수 있습니다.
- GET 요청은 로컬 `json-server`에서 읽습니다.
- 모바일과 넓은 화면을 위한 반응형 레이아웃을 제공합니다.
- Flutter 정적 분석과 전체 테스트가 통과합니다.
- Flutter Web release 빌드가 성공합니다.

## 아직 완료하지 못했거나 제한된 것

- 새 기록은 서버나 로컬 데이터베이스에 저장되지 않으며 새로고침 후 사라집니다.
- 감정과 생활 태그는 고정된 초기 목록이며 실제 사용자 테스트로 검증하지 않았습니다.
- 주간 리포트의 7일 요약은 `db.json`의 고정 모의 데이터입니다.
- 실제 사용자 인터뷰와 사용성 테스트는 아직 진행하지 않았습니다.
- DailyBean 리뷰와 별점 데이터는 기록했지만 공식 스토어 원본 캡처는 별도 보관이 필요합니다.
- 감정 선택 단계의 망설임은 설계 가설이며 DailyBean 리뷰가 직접 증명한 사실이 아닙니다.
- 배포 URL은 없으며 1분 YouTube 데모 영상으로 시연합니다.

## 디자인 결정의 변화

1. 메모를 필수처럼 보이게 하던 표현을 `선택`으로 명확히 바꿨습니다.
2. 홈에서 모든 기능을 보여 주지 않고 `빠른 선택 + 오늘 요약`에 집중했습니다.
3. 전체 생활 태그는 기록하기 화면으로 옮겼습니다.
4. 앱 내부 AI 심리 분석을 제외하고 AI는 디자인 검토에만 사용했습니다.
5. PPT 8페이지는 실제 Flutter Before/After 캡처를 사용하고 Before를 폐기안으로 표시했습니다.

- 로컬 영구 저장이 필요한지 검토하되 이번 제출 범위에는 추가하지 않습니다.

- `감정 1개는 필수, 태그와 메모는 선택` 규칙을 사용자가 설명할 수 있는지 확인합니다.
