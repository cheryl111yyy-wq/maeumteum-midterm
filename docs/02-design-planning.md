# 제품 및 경험 기획

## 1. 한 페이지 앱 요약

### 제품 목표

바쁜 대학생이 긴 일기를 쓰지 않아도 오늘의 감정을 남기고, 최근 7일의 기록을 빠르게 돌아볼 수 있게 돕습니다.

### 제품 이름

- 한국어: 마음틈
- 영어: MoodPause
- 의미: 바쁜 일상에서 자신의 마음을 잠깐 들여다보는 틈

### 대상 사용자

감정은 기록하고 싶지만 매일 긴 일기를 쓰는 일에는 부담을 느끼는 대학생입니다.

### 해결할 문제

사용자가 기록을 시작할 때 `어디까지 입력해야 한 번의 기록이 완성되는지` 바로 알 수 있게 합니다. 감정 하나를 최소 성공 기준으로 두고 생활 태그와 메모는 선택 사항으로 제공합니다.

### 근거의 경계

| 출처 | 알 수 있는 것 | 알 수 없는 것 |
|---|---|---|
| DailyBean R1 사용자 제공 리뷰 | 한 사용자가 앱 접속 실패와 많은 입력량을 경험 | 모든 사용자가 같은 문제를 겪는다는 사실 |
| DailyBean R2–R3 Google Play | 보상 경험과 개인화에 대한 보충 의견 | 감정 선택 단계의 부담을 직접 증명하는 근거 |
| Persona·Journey | 바쁜 대학생의 기록 부담에 대한 설계 가설 | 인터뷰로 검증된 사실 |
| Fishbone·5 Whys | `최소 기록의 성공 기준이 불명확하다`는 원인 가설 | 유일하게 확인된 원인 |

따라서 발표와 문서에서는 `설계 가설`, `근본 원인 가설`이라는 표현을 사용하고, 가설을 실제 사용자 조사 결과처럼 표현하지 않습니다.

### V2 핵심 가치

1. 짧고 간단한 감정 기록
2. 대학 생활 맥락과 감정의 연결
3. 한눈에 확인하는 최근 7일 회고

### 핵심 흐름

오늘 화면 → 감정 선택 → 선택적 생활 태그와 한 줄 메모 → 기록 완료 → 기록 달력 → 주간 리포트

## 2. 페르소나

> 이 페르소나는 설계 가설이며 실제 인터뷰를 완료한 결과가 아닙니다.

| 항목 | 내용 |
|---|---|
| 이름 | 김서연 |
| 나이 | 21세 |
| 신분 | 한국 대학교 2학년 |
| 생활 상황 | 수업, 과제, 시험, 아르바이트, 친구, 휴식 |
| 목표 | 적은 조작으로 오늘의 감정을 남기고 주말에 빠르게 돌아보기 |
| 불편 | 바쁠 때 긴 일기를 쓰기 어렵고 선택지가 많으면 시작을 망설임 |
| 기기 | 휴대전화, 주로 수업 후·취침 전·이동 중 사용 |
| 사용 빈도 가설 | 기록할 의향이 있을 때 사용하며 매일 연속 기록을 강요하지 않음 |
| 기대 경험 | 이해하기 쉬운 조작, 선택 가능한 글 입력, 빠르게 읽히는 회고 |
| 성공 기준 | 설명 없이 기록을 완료하고 최근 7일 요약을 이해함 |

## 3. 사용자 여정

과제: 김서연이 시험을 마친 뒤 마음틈에 오늘의 감정을 기록하고, 주말에 최근 기록을 돌아본다.

| 단계 | 행동 | 생각 | 감정 | 디자인 기회 |
|---|---|---|---|---|
| 1. 기록 필요 | 시험이 끝난 뒤 상태를 남기고 싶음 | 오늘은 조금 지쳤다 | 피로 | 앱을 열면 기록 시작점이 바로 보임 |
| 2. 앱 열기 | 오늘 화면으로 이동 | 빨리 끝내고 싶다 | 중립 | 감정 선택과 짧은 안내를 먼저 표시 |
| 3. 감정 선택 | `가라앉음` 또는 `평온` 선택 | 이 감정이 지금의 나와 맞나 | 망설임 가능 | 아이콘과 한국어 라벨을 함께 제공 |
| 4. 상황 추가 | `시험` 태그 선택 | 오늘은 시험 때문이었구나 | 점차 명확 | 자주 쓰는 태그를 바로 보여 줌 |
| 5. 기록 완료 | 메모는 선택으로 두고 완료 | 기록했다 | 가벼움 | 완료 상태와 오늘 요약을 명확히 표시 |
| 6. 기록 회고 | 달력과 최근 7일 리포트 확인 | 이번 주에는 어땠지 | 궁금함 | 중립적인 문장과 간결한 요약 |

### 확장 정보

| 항목 | 내용 |
|---|---|
| 사용 기기 | 휴대전화, 한 손 조작, 주요 버튼을 엄지로 닿기 쉬운 위치에 배치, 작은 화면은 스크롤 |
| AI 활용 기회 | 디자인 반론자로 태그·메모 필수화, 홈 정보 과밀, 근거 경계를 검토 |
| 관련 원칙 | P01 상태 가시성, P03 사용자 통제, P04 일관성, P06 인식, P08 간결성 |
| 필요한 데이터 | 현재 날짜, 감정 선택지, 생활 태그, 사용자 선택, 기록 날짜, `weeklyReport` 모의 결과 |

## 4. 여섯 관점 피시본

핵심 문제: 사용자가 일상 기록 과정에서 입력 부담을 느낄 가능성이 있다.

| 관점 | 가능한 원인 |
|---|---|
| 사용자 | 바쁠 때 기록 동기가 약해짐, 기록의 가치가 불명확함 |
| 프로세스 | 기록 화면까지의 단계가 많음, 필수와 선택의 구분이 없음 |
| UI | 주요 행동이 두드러지지 않음, 선택 상태가 명확하지 않음 |
| 콘텐츠 | 감정 선택지가 이해하기 어려움, 글 입력이 필수처럼 보임 |
| 기기 | 한 손 조작이 어려움, 작은 화면에서 정보가 과밀함 |
| 피드백 | 완료 상태가 보이지 않음, 로딩·오류 상황을 이해하기 어려움 |

우선순위가 가장 높은 문제: **필수 항목과 선택 항목이 명확하게 구분되지 않는 것**

## 5. 5 Whys

### Why 1

사용자가 기록 과정에서 부담을 느끼는 이유는 무엇인가?

감정 외에도 여러 정보를 한 번에 입력해야 한다고 느낄 수 있기 때문입니다.

### Why 2

여러 정보를 입력해야 한다고 느끼는 이유는 무엇인가?

어떤 항목이 필수이고 어떤 항목이 선택인지 즉시 알기 어렵기 때문입니다.

### Why 3

필수와 선택의 구분이 어려운 이유는 무엇인가?

입력 항목이 비슷한 시각적 비중으로 배치될 수 있기 때문입니다.

### Why 4

항목의 시각적 비중이 비슷해지는 이유는 무엇인가?

기록의 풍부함과 빠른 시작을 동시에 얻으려 하기 때문입니다.

### Why 5

두 목표가 충돌하는 이유는 무엇인가?

제품이 `빠르게 남기는 최소 기록`을 첫 번째 성공 기준으로 명시하지 않았기 때문입니다.

### 근본 원인 가설과 디자인 결정

근본 원인 가설: 사용자가 적은 조작으로 유효한 기록을 완료할 수 있어야 한다는 기준이 먼저 정해져야 합니다.

디자인 결정:

- 감정 선택은 유일한 필수 항목
- 생활 태그와 한 줄 메모는 선택 항목으로 명시
- 오늘 화면과 기록 화면에서 선택 상태를 명확히 표시
- 기록 완료 후 빈 화면이 아니라 오늘 요약 표시

## 6. 경쟁 앱 개선 매트릭스

| 발견 | 개선 방향 | 디자인 행동 | 화면 |
|---|---|---|---|
| DailyBean의 빠른 기록과 개인화 | 빠른 선택은 유지하고 복잡한 보상·테마 상점은 제외 | 오늘 화면에서 감정 선택, 전체 태그는 기록 화면에 배치 | 오늘, 기록하기 |
| R1의 접속 실패와 입력 과다 | 실패 복구와 최소 기록 강화 | 감정 1개 필수, 태그·메모 선택, Loading·Error·Retry 제공 | 오늘, 기록하기 |
| R2·R3의 보상 확률과 광고 의견 | 무작위 보상으로 추가 부담을 만들지 않음 | 완료 피드백과 중립 리포트 사용 | 오늘, 리포트 |
| 요청 상태가 흐름을 방해할 수 있음 | 상태를 명확히 표시 | 첫 GET은 `FutureBuilder`, 오류에는 재시도 제공 | 전체 |

## 7. 사용자 테스트 계획

이번 제출 전에는 실제 사용자 테스트를 완료하지 않았습니다. 다음 단계에서 아래 항목을 확인합니다.

| 테스트 | 관찰 항목 |
|---|---|
| 감정만 선택해 기록 완료 | 설명 없이 기록을 끝낼 수 있는가 |
| 태그 2개와 메모 입력 | 태그와 메모가 선택임을 이해하는가 |
| 지정 날짜의 기록 찾기 | 10초 안에 기록을 찾을 수 있는가 |
| 최근 7일 리포트 읽기 | 핵심 정보를 자신의 말로 설명할 수 있는가 |
| 빈 상태와 오류 상태 전환 | 문제를 이해하고 다시 시도할 수 있는가 |

테스트에서는 이름, 연락처와 같은 개인정보를 수집하지 않습니다.
