# 产品与体验规划

## 1. 一页式 App Summary

### 产品目标

帮助忙碌的大学生在不增加记录负担的前提下，留下当天的心情与生活情境，并通过简洁的最近 7 天回顾理解自己的记录。

### 产品名称

- 韩文：마음틈
- 英文：MoodPause
- 含义：心情的缝隙，留给自己的短暂片刻

### 目标用户

대학생 중 자신의 감정을 기록하고 싶지만, 긴 일기를 매일 작성하는 과정에는 부담을 느낄 수 있는 사용자.

中文：希望记录情绪，但可能觉得每天写长日记有负担的大学生。

### 要解决的问题

바쁜 대학생이 기록을 시작할 때 “어디까지 입력해야 한 번의 기록이 완성되는지” 바로 이해하도록 돕는다. 감정 하나를 최소 성공 기준으로 두고, 생활 태그와 메모는 선택 사항으로 제공한다.

### 证据边界

| 来源 | 能说明什么 | 不能说明什么 |
|---|---|---|
| DailyBean R1 사용자 제공 리뷰 | 一位 3 星用户明确报告应用偶尔打不开，并且记录时信息量太多 | 所有用户都会遇到同样问题 |
| DailyBean R2–R3 Google Play | 보상 경험과 개인화에 대한 보충 의견 | 直接证明情绪选择阶段的负担 |
| Persona·Journey | 忙碌大学生可能因输入要求不明确而犹豫的假设 | 已经通过访谈或评论验证 |
| Fishbone·5 Whys | 对“最小记录成功标准不明确”这一根因假设的设计分析 | 已被证实的唯一根因 |

因此，PPT 的正文统一使用“설계 가설”和“근본 원인 가설”，不把假设包装成用户研究事实。

### V2 核心价值

1. 짧고 간단한 감정 기록.
2. 대학 생활 맥락과 감정의 연결.
3. 한눈에 확인하는 최근 7일 회고.

### 核心流程

오늘 화면 → 감정 선택 → 선택적 생활 태그와 한 줄 메모 → 기록 완료 → 기록 달력 → 주간 리포트

## 2. 用户画像

> 性质：设计假设画像，不代表已经完成真实访谈。

| 项目 | 内容 |
|---|---|
| 姓名 | 김서연 |
| 年龄 | 21 岁 |
| 身份 | 韩国大学二年级学生 |
| 生活情境 | 上课、作业、考试、兼职、朋友、休息 |
| 主要目标 | 用很少的操作记录当天心情，并在周末快速回看 |
| 可能困难 | 忙时不想写长日记；选项过多时可能犹豫 |
| 使用设备 | 手机，主要在课后、睡前或通勤时使用 |
| 使用频率假设 | 有记录意愿时使用，不要求每日连续打卡 |
| 期望体验 | 操作直观、文字可选、回顾内容一眼能懂 |
| 成功标准 | 用户能独立完成记录，并理解最近 7 天的摘要 |

## 3. 用户旅程

任务：김서연이 시험을 마친 뒤 마음틈에서 오늘의 감정을 기록하고, 주말에 최근 기록을 돌아본다.

| 阶段 | 行为 | 想法 | 情绪 | 设计机会 |
|---|---|---|---|---|
| 1. 产生需求 | 考试结束后想记录状态 | “今天有点累。” | 疲惫 | 打开后直接看到记录入口 |
| 2. 打开 App | 进入 오늘 页面 | “快点记完就好。” | 中性 | 首页展示情绪选项与简短提示 |
| 3. 选择心情 | 选择“지침”或“평온” | “这个选项符合我吗？” | 可能犹豫 | 文字标签与图标共同出现 |
| 4. 加生活情境 | 选择“시험” | “今天主要是因为考试。” | 逐渐清晰 | 常用标签直接可见 |
| 5. 完成记录 | 可选写一句，然后提交 | “完成了。” | 轻松 | 明确完成状态与今日摘要 |
| 6. 回看记录 | 查看日历与最近 7 天报告 | “这一周是什么状态？” | 好奇 | 摘要简洁、措辞中性 |

## 4. 六视角鱼骨图

核心问题：일상 기록 과정에서 사용자가 입력 부담을 느낄 가능성이 있다.

| 视角 | 可能原因 |
|---|---|
| 사용자 | 忙碌时缺少记录动力；不确定记录是否值得 |
| 프로세스 | 进入记录页的步骤过多；必填项与可选项没有区分 |
| UI | 主要操作不突出；选中状态不够清楚 |
| 콘텐츠 | 心情选项难理解；文字输入被误认为必填 |
| 기기 | 单手操作困难；较小屏幕上出现拥挤 |
| 피드백 | 完成状态不明显；加载或失败时不知道发生了什么 |

优先级最高的问题：**必填项与可选项没有清楚区分。**

## 5. 5 Whys

### Why 1

사용자가 기록 과정에서 부담을 느끼는 이유는 무엇인가?

답: 감정 외에 여러 정보를 한 번에 입력해야 한다고 느낄 수 있기 때문이다.

### Why 2

여러 정보를 입력해야 한다고 느끼는 이유는 무엇인가?

답: 어떤 항목이 필수이고 어떤 항목이 선택인지 즉시 알기 어렵기 때문이다.

### Why 3

필수와 선택의 구분이 어려운 이유는 무엇인가?

답: 입력 항목이 같은 시각적 비중으로 배치될 수 있기 때문이다.

### Why 4

항목의 비중이 같아지는 이유는 무엇인가?

답: 기록의 풍부함과 기록 시작의 용이성을 동시에 확보하려 하기 때문이다.

### Why 5

그 두 목표가 충돌하는 이유는 무엇인가?

답: 제품이 “빠르게 남기는 최소 기록”을 첫 번째 성공 기준으로 명시하지 않았기 때문이다.

### 根因假设与设计决策

根因假设：产品的第一目标应当是让用户以少量操作完成一次有效记录。

设计决策：

- 心情选择是唯一必填项。
- 生活标签和一句话备注明确标记为可选。
- 首页与记录页均提供清楚的选中状态。
- 记录完成后显示今日摘要，而不是直接跳转到空白页面。

## 6. 竞品改进矩阵

| 发现 | 改进方向 | 设计动作 | 对应界面 |
|---|---|---|---|
| DailyBean 的快速记录和个性化价值 | 保留快速选择，但不复制复杂奖励与主题商店 | 首页直接选择心情；常用标签前移，完整标签放入记录页 | 오늘、기록하기 |
| R1 描述应用偶尔打不开与记录信息过多 | 让失败可恢复，并缩短最小记录 | 情绪 1 个必填，标签·메모 선택；Loading·Error·Retry 명시 | 오늘、기록하기 |
| R2/R3 对奖励概率和广告体验提出意见 | 不用随机奖励制造额外干扰 | 以完成反馈和中性周报代替游戏化机制 | 오늘、리포트 |
| 请求和使用反馈会影响连续性 | 状态清晰 | FutureBuilder 处理初次 GET，Error 提供重试 | 全 App |

## 7. 用户测试计划

本次提交尚未进行真实用户测试，以下为下一阶段计划：

| 测试任务 | 观察指标 |
|---|---|
| 打开 App 后完成一条只有心情的记录 | 是否能在不阅读说明的情况下完成 |
| 选择两个生活标签并写一句备注 | 是否理解标签与文字均可选 |
| 从历史页找到指定日期的记录 | 能否在 10 秒内找到 |
| 阅读最近 7 天报告 | 能否用自己的话复述主要信息 |
| 切换到空数据与错误状态 | 是否理解发生了什么，是否知道如何重试 |

测试期间不记录真实姓名、联系方式或其他敏感个人信息。
