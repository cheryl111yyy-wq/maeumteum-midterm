# 셀프 논증

## 전체 논증의 위치

- DailyBean R1: 앱이 자주 열리지 않고, 기분 하나를 기록하려 해도 선택할 정보가 너무 많다는 3점 리뷰.
- DailyBean R2–R3: 보상·광고 경험과 개인화 가치에 대한 보충 단서.
- Persona·Journey·P05/P06: R1의 입력 부담을 감정 선택 단계의 **설계 가설**로 구체화.
- 5 Whys: 최소 기록의 성공 기준이 불명확하다는 **근본 원인 가설**.
- 본문 8장의 두 쟁점: 그 가설을 실제 화면 결정으로 옮긴 뒤 AI 반론으로 검증.

## 쟁점 1. 생활 태그와 메모를 필수로 설정할 것인가?

### 내 주장

생활 태그와 메모를 필수로 받으면 7일 회고에 배경 정보가 늘어나 사용자가 감정의 맥락을 더 잘 이해할 수 있다.

### AI 반론

필수 입력은 기록 시작 자체를 막는다. 특히 바쁜 대학생이 기억을 더듬어 태그와 메모를 억지로 작성하면 데이터의 정확성도 낮아질 수 있다.

### 스스로 찾은 반론

마음틈의 첫 성공 기준은 “감정 하나로 유효한 기록 완성”이다. 모든 항목을 필수로 만들면 기록의 풍부함을 위해 시작 가능성을 포기하는 셈이다.

### 재반론

맥락 정보는 가치가 있지만 완료 조건이 될 필요는 없다. 감정 하나를 필수로 두고 태그와 메모를 선택 사항으로 제공하면, 빠른 사용자와 자세한 사용자를 동시에 수용할 수 있다.

### 수정 사항

- 감정 선택만 `필수`로 표시한다.
- 생활 태그와 메모는 `선택`으로 표시한다.
- 감정 없이 제출할 때만 짧은 오류와 수정 방법을 보여 준다.
- 태그는 다시 눌러 해제할 수 있고, 메모는 120자로 제한한다.
- 전체 필수 폐기안은 제작 단계에서 Flutter Web으로 캡처해 `screenshots/record_before.png`로 보관하고, 최종 App의 실행 경로에는 포함하지 않는다.

### 최종 결론

**유지**: 감정 1개만 필수, 생활 태그와 메모는 선택으로 유지한다.

### 근거

- P03 사용자 통제와 자유: 기록 범위를 사용자가 결정한다.
- P05 오류 예방: 필수와 선택을 제출 전에 즉시 구분한다.
- P08 간결한 디자인: 최소 성공 경로에 필요한 정보만 남긴다.

### 전·후 화면

- 전: 감정·태그·메모를 모두 `필수`로 표시한 폐기안을 Flutter Web으로 캡처해 `screenshots/record_before.png`로 보관했다. 이 비교 상태는 최종 App의 실행 경로에는 포함하지 않는다.
- 후: 현재 기록 화면은 감정만 필수이고, 태그·메모는 선택이다.

### 코드 근거

최종 앱의 `lib/screens/record_screen.dart`에는 `P03`·`P05` 주석, 빈 감정 검증, `maxLength: 120` 입력 제한만 남긴다.

## 쟁점 2. 모든 생활 태그를 홈에 보여 줄 것인가?

### 내 주장

대학생활 태그는 마음틈의 핵심 개인화 요소이므로 수업, 과제, 시험, 아르바이트 등 모든 태그를 홈에서 바로 보여 주는 것이 좋다.

### AI 반론

날짜, 감정 선택, 전체 태그, 오늘 기록, 내비게이션이 한 화면에 겹치면 정보 계층이 약해진다. 작은 화면에서는 스크롤이 길어지고 모든 태그가 필수처럼 보일 수 있다.

### 스스로 찾은 반론

개인화를 강조하는 것과 모든 선택지를 한 화면에 노출하는 것은 다르다. 홈은 기록 시작을 돕고, 전체 태그는 실제 기록 흐름에서 제공하는 편이 역할이 더 분명하다.

### 재반론

태그 초점은 유지하되 홈에는 감정과 자주 쓰는 태그 일부만 보여 주고, 전체 목록은 기록 페이지에서 점진적으로 공개한다.

### 수정 사항

- 홈의 주 행동을 감정 선택과 기록 시작에 집중시킨다.
- 홈에는 자주 쓰는 태그 일부만 노출한다.
- 전체 태그는 기록 페이지에서 모두 선택할 수 있다.
- 넓은 화면에서는 `LayoutBuilder`로 두 열을 사용하고, 좁은 화면은 세로 스크롤을 유지한다.

### 최종 결론

**수정**: 모든 태그의 홈 노출을 폐기하고 “홈의 빠른 진입 + 기록 페이지의 전체 선택”으로 바꾼다.

### 근거

- P04 일관성과 표준: 홈과 기록 페이지가 같은 태그 선택기를 사용한다.
- P07 유연성과 효율성: 자주 쓰는 태그는 빠르게, 전체 목록은 필요할 때 선택한다.
- P08 간결한 디자인: 첫 화면의 핵심 행동을 약화하지 않는다.

### 전·후 화면

- 전: 홈 한 화면에 전체 태그와 관련 기능을 배치하는 안을 검토했다.
- 후: 홈은 빠른 시작 화면으로 유지하고, 전체 태그는 기록 화면에서 선택한다.

### 코드 근거

`lib/screens/today_screen.dart`의 `LayoutBuilder`·`Wrap`, `lib/widgets/selectors.dart`의 `SituationSelector`.
