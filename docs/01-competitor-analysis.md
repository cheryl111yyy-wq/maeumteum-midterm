# DailyBean 竞品分析

## 分析目的

选择 DailyBean，是因为它与 마음틈 都围绕心情、日常活动和记录回顾展开。竞品分析的目的在于识别值得学习的设计价值，并找到一个适合大学生场景、可由本次 Flutter 原型承载的改进机会。本分析不把 DailyBean 描述成所谓“功能缺失”的产品。

## 可核验的产品事实

截至公开页面可确认，DailyBean 提供心情、活动、文字、照片、自定义分类与图标、主题、日历、报告和隐私锁定等功能；其官方介绍强调通过点击图标减少长日记负担。部分高级主题、分析、照片与广告移除属于付费范围。

## Nielsen 原则分析

| 观察到的 DailyBean 设计 | Nielsen 原则 | 设计价值 | 对 마음틈 的启示 |
|---|---|---|---|
| 用图标快速记录心情与活动 | P02 现实世界匹配 | 降低表达门槛 | 保留文字标签与图形辅助，不只依赖图标 |
| 记录后有可视化的心情与活动反馈 | P01 系统状态可见性 | 让用户知道记录生效 | 选中、完成、加载、错误都必须有明确状态 |
| 支持自定义分类与主题 | P03 用户控制与自由 | 用户能调整体验 | 本期不复制主题编辑器，但允许标签多选和取消 |
| 主流程围绕日期组织 | P04 一致性与标准 | 用户容易建立心智模型 | 今日、记录、报告的日期表达保持一致 |
| 采用图标优先的快速记录 | P06 识别优于回忆 | 用户无需记住操作 | 心情与场景都通过可见选项完成 |
| 报告提供心情与活动回顾 | P08 简洁、美观、低负担 | 大量信息可被压缩 | 周报只保留记录天数、常见心情、常见标签和中性总结 |
| 核心操作与统计属于产品内容 | P07 灵活高效 | 用户可按目的使用 | 首页直接开始记录，历史与周报低频进入 |

### 三条评论到四类体验的编码

三条评论并不等于最多只能得到三个分析类型。一条较长评论可以同时支持多个体验类型，因此本项目采用“评论—体验编码”，而不是把同一评论当作多条独立评论重复计算。

| 体验类型 | 支持评论 | 分析边界 |
|---|---|---|
| 기록 입력 부담 | R1 | 评论者直接指出要记一个心情却要面对过多信息；这是单条真实体验，不代表所有用户 |
| 접속·안정성 | R1 | 评论者同时报告应用经常打不开；原型用 Loading、Error、Retry 和状态说明回应可恢复性 |
| 奖励透明性 | R2、R3 | 两条评论都提到获得奖励的概率或结果不透明 |
| 广告与重复体验 | R2、R3 | 说明广告观看和重复获取过程可能形成负担 |
| 个性化价值 | R3 | 主题定制得到正面评价，应保留个性化方向 |

采集规则：

1. 只使用公开 App Store 或 Google Play 评论。
2. 保留日期、星级、平台与必要原文。
3. 隐藏评论者姓名。
4. 区分正面、负面、功能需求、使用障碍和其他意见。
5. 每条评论都要写“设计启示”，不能只堆截图。
6. 不把个别评论扩大为所有用户的结论。

## 竞品发现到 V2 设计的对应表

| 竞品分析发现 | 设计机会 | 마음틈 V2 改进 | 对应页面 |
|---|---|---|---|
| R1 报告“只想记心情却要选很多信息” | 明确最小记录成功标准 | 情绪 1 个必填，生活标签和备注均标为可选 | 오늘、기록하기 |
| R1 同时报告应用经常打不开 | 让失败状态可理解并能恢复 | Loading、Error、Retry、Empty 均为真实界面 | 全 App |
| DailyBean 用少量点击降低记录负担 | 继续缩短必填流程 | 首页直接显示心情；标签与文字均可选 | 오늘、기록하기 |
| DailyBean 已支持多种活动分类 | 用目标用户的场景重新组织信息 | 大学生活标签更靠前，周报统计标签 | 오늘、기록하기、주간 리포트 |
| DailyBean 已提供日历与报告 | 提升快速阅读性 | 周报集中展示记录天数、常见心情、常见标签 | 주간 리포트 |
| 评论中出现奖励与广告负担 | 不用随机奖励制造额外干扰 | 以非游戏化的完成反馈和中性周报为中心 | 오늘、주간 리포트 |
| 数据导出与长期保管受到关注 | 不夸大原型的保存能力 | 明确“本次运行临时状态”，把导出列为未来验证项 | 기록하기、README |
| R3 肯定主题个性化 | 保留生活标签的个人化价值 | 首页显示常用标签，完整标签放入记录页 | 오늘、기록하기 |
| 请求与流程状态可能影响连续性 | 让请求状态可理解 | FutureBuilder + 可重试的 Loading、Error、Empty、Success | 全 App |

## 严谨性边界

- R1은 한 사용자가 접속 실패와 과도한 입력량을 직접 보고한 사례다. 전체 사용자에게 같은 문제가 얼마나 퍼져 있는지는 아직 검증되지 않았다.
- “감정 선택 단계에서 망설인다”는 R1의 입력 부담 단서와 Persona·Journey·P05/P06을 결합한 설계 가설이며, 사용자 테스트가 필요하다.
- “突出大学生活标签”是设计聚焦，不代表 DailyBean 没有活动分类。
- “更简洁的周报”是信息组织提案，不代表 DailyBean 没有报告。
- 本原型不会根据情绪记录诊断心理问题，也不会把标签相关性写成因果关系。
