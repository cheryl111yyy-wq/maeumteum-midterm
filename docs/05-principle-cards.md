# Nielsen 원칙 카드

> 제출 전에 강사가 제공한 원칙 카드 번호와 대조해야 합니다. 이 문서는 Nielsen의 대표적인 10가지 휴리스틱을 프로젝트에 맞게 정리한 것입니다.

## P01 시스템 상태의 가시성

- 원칙: 시스템은 현재 상태를 사용자에게 지속적으로 알려야 합니다.
- 근거: 로딩, 선택, 완료, 오류 상태가 보여야 사용자가 같은 행동을 반복하지 않습니다.
- 적용: `FutureBuilder`의 waiting·error·data 상태, 선택 체크, 완료 요약
- 시연: 로딩 상태를 열고, 오류 상태와 정상 상태를 비교합니다.
- 코드: `lib/main.dart`, `lib/widgets/common_widgets.dart`, `lib/widgets/selectors.dart`

## P02 현실 세계와의 일치

- 원칙: 시스템의 언어와 개념이 사용자의 실제 경험과 맞아야 합니다.
- 근거: 대학생은 수업, 과제, 시험 같은 익숙한 단어를 빠르게 이해합니다.
- 적용: 대학 생활 태그와 자연스러운 한국어 회고 문장
- 시연: 기록하기 화면에서 `과제`와 `시험`을 선택합니다.
- 코드: `lib/widgets/selectors.dart`, `mock_server/db.json`

## P03 사용자 통제와 자유

- 원칙: 사용자는 선택을 취소하고, 뒤로 가고, 불필요한 단계를 건너뛸 수 있어야 합니다.
- 근거: R1은 감정 하나를 기록하려 해도 선택 정보가 너무 많다고 했습니다.
- 적용: 생활 태그와 메모는 선택 사항이며, 태그는 다시 눌러 해제할 수 있습니다.
- 시연: 감정만 선택해 완료하고, 다시 들어가 태그를 켰다가 끕니다.
- 코드: `lib/screens/record_screen.dart`

## P04 일관성과 표준

- 원칙: 같은 개념, 조작과 시각 구조는 일관되게 유지합니다.
- 근거: 일관된 구조가 학습 부담을 줄입니다.
- 적용: 감정 목록, 날짜 형식, 카드 모서리, 하단 내비게이션을 통일합니다.
- 시연: 오늘, 기록, 리포트 화면을 차례로 전환합니다.
- 코드: `lib/theme/app_theme.dart`, `lib/shell.dart`

## P05 오류 예방

- 원칙: 오류가 생기기 전에 막고, 필요한 조건은 명확히 설명합니다.
- 근거: 사용자가 메모를 필수로 오해할 수 있습니다.
- 적용: 영역 제목에 `필수`와 `선택`을 표시하고, 감정이 없으면 제출을 막습니다.
- 시연: 감정을 고르지 않고 `기록 완료`를 누릅니다.
- 코드: `lib/screens/record_screen.dart`

## P06 기억보다 인식

- 원칙: 선택지와 행동을 화면에 보여 주어 기억 부담을 줄입니다.
- 근거: 사용자는 현재 화면에서 감정과 자주 쓰는 태그를 확인해야 합니다.
- 적용: 아이콘과 한국어 라벨, 기록 날짜의 감정 표시
- 시연: 안내를 읽지 않고도 오늘 화면에서 감정을 선택합니다.
- 코드: `lib/widgets/selectors.dart`, `lib/screens/history_screen.dart`

## P07 유연성과 효율성

- 원칙: 숙련도와 상황에 따라 효율적인 경로를 제공합니다.
- 근거: 자주 쓰는 기록은 짧게, 가끔 쓰는 확인은 더 자세하게 만들 수 있습니다.
- 적용: 오늘 화면의 빠른 선택, 기록 화면의 전체 태그, 기록 화면의 BottomSheet
- 시연: 오늘 화면에서 감정을 고른 뒤 바로 기록을 완료합니다.
- 코드: `lib/screens/today_screen.dart`, `lib/screens/history_screen.dart`

## P08 간결한 디자인

- 원칙: 현재 작업을 지원하지 않는 정보는 덜어냅니다.
- 근거: 정보가 많으면 기록과 회고의 부담이 커집니다.
- 적용: 주간 리포트는 핵심 요약과 중립 문장만 표시합니다.
- 시연: 기록 화면과 주간 리포트의 정보 밀도를 비교합니다.
- 코드: `lib/screens/report_screen.dart`

## P09 오류 인식, 진단과 복구

- 원칙: 문제를 쉬운 말로 설명하고 복구할 수 있는 행동을 제공합니다.
- 근거: 로컬 서버가 실행되지 않거나 요청이 실패할 수 있습니다.
- 적용: `FutureBuilder.hasError`에서 서버 확인 안내와 `다시 시도`를 제공합니다.
- 시연: 상태 메뉴에서 오류 상태를 연 뒤 정상 데이터로 돌아옵니다.
- 코드: `lib/widgets/common_widgets.dart`, `lib/main.dart`

## P10 도움말과 문서

- 원칙: 필요한 순간에 시스템의 기능과 한계를 이해할 수 있게 합니다.
- 근거: 프로토타입은 기록을 영구 저장하지 않습니다.
- 적용: 기록 화면의 임시 상태 안내, 주간 리포트의 중립 문장, README의 실행 방법
- 시연: 기록 화면 아래 안내와 README를 확인합니다.
- 코드: `lib/screens/record_screen.dart`, `README.md`
